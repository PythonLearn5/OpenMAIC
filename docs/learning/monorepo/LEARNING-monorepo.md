# 1. Monorepo 是什么？

Monorepo（单一代码仓库）：在一个 Git 仓库中管理多个项目、应用或共享代码包。

例如，OpenMAIC 可以把 Web 应用、公共组件、工具库等放在同一个仓库中统一管理。

## 1.1 传统多仓库 vs Monorepo

### 多仓库（Multi-repo）

```
project-web/       # Web 应用
project-ui/        # UI 组件库
project-utils/     # 工具库
```

每个项目独立维护，版本、依赖和发布流程可能需要分别管理。

### Monorepo（单一仓库）

```
openmaic/
├── apps/
│   └── web/       # Web 应用
├── packages/
│   ├── ui/        # 共享 UI 组件
│   └── utils/     # 共享工具库
├── package.json
└── pnpm-workspace.yaml
```

多个项目集中管理，可以共享依赖、统一开发和协同修改。

以上是示意结构，并不代表 OpenMAIC 仓库的实际目录布局。

## 1.2 Monorepo 的主要优点

- 代码复用：多个项目可以直接引用共享组件和工具库。
- 统一依赖：集中管理依赖版本，减少重复安装。
- 协同修改：修改共享代码时，可以同时更新使用它的项目。
- 统一工具链：可以统一执行检查、测试、构建等任务。

需要注意：Monorepo 不等于所有代码都必须打包成一个应用，也不意味着所有项目必须一起发布。

## 1.3 它和 pnpm workspace、Rollup、Turbopack 的关系

| 技术             | 作用                           | 类比         |
| -------------- | ---------------------------- | ---------- |
| Monorepo       | 组织多个项目的代码                    | 一栋办公楼      |
| pnpm workspace | 管理仓库中的多个包及其依赖                | 办公室管理系统    |
| Rollup         | 将模块打包成发布产物                   | 把零散零件组装成产品 |
| Turbopack      | 为 Next.js 等开发流程提供快速打包与模块处理能力 | 加速开发现场的装配线 |

核心区别： Monorepo 是代码组织方式，pnpm workspace 是包管理机制，Rollup 和 Turbopack 是构建工具。它们解决的是不同层面的问题，可以配合使用。

下一步建议理解 pnpm workspace：它是 Monorepo 在前端项目中最常见的实现基础之一。

## 1.4 Monorepo 是一种代码仓库组织理念和工程管理模式，而不是一个具体的软件或工具。

不过更准确地说，它既是一种架构选择，也是一种工程实践。

举个例子：

假设你开发一个 AI 平台，有三个项目：

```
ai-platform/
├── web/          # Next.js 前端
├── admin/        # 管理后台
└── ai-core/      # AI 核心模块
```

只要这三个项目都放在同一个 Git 仓库里管理，你就采用了 Monorepo 模式。

但 Monorepo 本身并不负责安装依赖、编译代码或管理构建任务。

| 层级      | 解决的问题        | 常用工具                 |
| ------- | ------------ | -------------------- |
| 仓库组织理念  | 多个项目放在哪里管理   | Monorepo             |
| 包管理     | 项目之间如何共享依赖   | pnpm Workspace       |
| 任务编排    | 项目按什么顺序构建、测试 | Turborepo、Nx         |
| 构建打包    | 源代码如何转换、打包   | Rollup、Turbopack、tsc |
| 版本管理与发布 | 多个包如何统一发版    | Changesets 等         |

注意：这些工具并非必须全部使用，也有其他替代方案。
